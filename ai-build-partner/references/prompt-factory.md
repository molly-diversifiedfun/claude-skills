# Prompt Factory — generating research-grade prompts from buyer context

> **When the buyer needs external knowledge, don't guess. Generate a prompt they can run.**

## The pattern

The Build Partner knows the buyer's context deeply — product type, audience, price, one-liner, kill-gate signals, stuck patterns, constraints. But it's NOT a search engine, a market research tool, or a platform expert. When the buyer hits a moment that requires external knowledge, the skill:

1. **Detects** the need (buyer asks a question or a module step requires knowledge the skill doesn't contain)
2. **Pulls context** from `.unstuck/context.md` — product name, type, audience, price, one-liner, constraints, hours/week, kill-gate quotes, anything relevant
3. **Generates** a self-contained prompt pre-filled with their specifics
4. **Tells them** where to run it and how
5. **Tells them** what to bring back

## How to present the prompt to the buyer

```
Here's a research prompt built from your project context. Run it in a separate conversation:

**Where to run it:** Open a new Claude or ChatGPT conversation. Turn on web search / research mode if available.

**The prompt:**
---
[generated prompt here]
---

**When you're done:** Come back here and paste the key finding. I'll save it to your context and we'll keep going.
```

## When to fire (detection rules)

Generate a prompt instead of answering directly when ANY of these are true:

- The answer depends on **current market data** (pricing, competitors, platforms, tools)
- The answer depends on **the buyer's specific industry** and you'd be guessing at norms
- The buyer asks a **"which one should I use"** question about tools, platforms, or services
- The buyer asks a **"what do people pay for this"** question
- The buyer asks a **"where is my audience"** question about channels or communities
- A module step says **"research needed"** or the buyer needs data you don't have
- The buyer asks **"how do I set up [specific tool]"** — platform UIs change frequently, don't hardcode steps

Do NOT fire the prompt factory for:
- Methodology questions (the skill IS the answer)
- Emotional moments (they need a response, not a research assignment)
- Context questions (read the context file, don't outsource it)
- Questions the kill-gate data already answers

## Prompt structure (every generated prompt follows this shape)

```
[One sentence stating exactly what they need to find out]

Context about my project:
- Product: [from C.1 + C.3]
- Audience: [from C.2]
- Price point: [from D.3, if set]
- Product type: [from C.3 — app, course, community, etc.]
- [Any other relevant context field]

What I need:
- [Specific deliverable — a recommendation, a comparison table, a list, a strategy]

Constraints:
- [Hours/week from A.4]
- [Technical skill level — infer from product type and their language]
- [Budget constraints if mentioned]
- [Timeline — "I'm launching in [N] days"]

Output format:
- [Table, ranked list, decision with rationale, step-by-step — whatever the module needs]
- Give me ONE recommendation, not a list of 5 options to evaluate
- If you recommend a tool, tell me the exact free tier limits and what I'd pay at my scale

Don't:
- Recommend enterprise solutions for a solo side project
- Suggest I "evaluate multiple options" — pick one and tell me why
- Give me a 2023 answer — check current pricing and features
```

## Context fields to pull (reference)

| Context section | What it contains | When to include |
|---|---|---|
| C.1 | Project name | Always |
| C.2 | Audience / persona | For market, copy, channel research |
| C.3 | One-liner | Always |
| D.3 | Price | For pricing, platform, checkout research |
| D.7 | Warm list / audience channels | For channel and distribution research |
| A.4 | Hours/week | For tool complexity decisions |
| A.5 | Technical skill | For build-vs-buy and stack decisions |
| E.1 | What exists (toy/V1 description) | For integration and delivery research |
| E.2 | Current stack | For compatibility research |
| Kill-gate signals | Quotes from real users | For copy, positioning, objection research |

## Example: tech stack research prompt (generated by pick-my-stack)

The buyer says: "what should I use to build this?"

Build Partner reads context, generates:

```
I need to pick a tech stack for my side project. I'm building it nights and weekends with limited time, so I need the fastest path to something live — not the best architecture.

Context:
- Product: Notion template for new engineering managers
- Type: digital download (Notion template + PDF)
- Audience: newly promoted EMs at mid-stage startups
- Price: $29 one-time
- My skills: I'm a PM, not an engineer. I can use no-code tools and copy-paste code but I'm not building a React app.
- Hours/week: 8
- Timeline: I want to launch in 14 days

What I need:
- Landing page: where to build it (one recommendation)
- Checkout: how to accept $29 payments (one recommendation)
- Delivery: how the buyer gets the Notion template + PDF after purchase (one recommendation)
- Email: how to collect emails + send a 3-email post-purchase sequence (one recommendation)

For each: name the tool, confirm it has a free tier or what it costs, and tell me setup time in minutes. I want the total stack cost under $20/month and total setup under 2 hours.

Give me a table: Tool | Cost | Setup time | Why this one.
```

The buyer runs this with research on, gets a specific recommendation, comes back, Build Partner saves it to E.2.

## Example: buyer persona research prompt (generated by any module that needs audience depth)

The buyer says: "I don't really know who my buyer is beyond the basics"

Build Partner reads context, generates:

```
I need to understand my target buyer better so I can write copy and position my product.

My product: a spec-writing course for junior PMs at SaaS companies
My one-liner: "I'm building a spec-writing course for junior PMs so they can write one-pagers that get buy-in instead of PRDs that get ignored."
My price: $49

What I need to understand about junior PMs at SaaS companies:
1. Where do they hang out online? (Slack communities, subreddits, newsletters, Twitter accounts they follow)
2. What do they currently pay for professional development? (courses, books, subscriptions — with price ranges)
3. What are the top 3 frustrations they talk about publicly? (search Reddit, LinkedIn, Glassdoor)
4. Who are the 3-5 existing products/courses competing for their attention? (with prices)
5. What language do they use to describe the "PRD problem"? (exact phrases, not my paraphrase)

Output as 5 numbered sections. For each, cite where you found it (subreddit name, community name, specific post if possible). I need real language from real people, not marketing personas.
```

## Example: landing page copy prompt (generated by T11 or landing-page module)

```
Write landing page copy for my product. Use the real quotes from my early users — don't invent testimonials.

Product: [one-liner from C.3]
Price: [$X from D.3]
Audience: [from C.2]

Real quotes from people who tried it (from my outreach):
- "[quote 1 from kill-gate signals]" — [name], [role]
- "[quote 2]" — [name], [role]
- "[quote 3]" — [name], [role]

The before/after:
- Before: [the Z-before from one-liner]
- After: [the Z-after from one-liner]

Write 8 sections:
1. Hero: headline + subheadline + CTA button text
2. Problem: the before state (use the real quotes above, not made-up pain points)
3. Solution: what changes
4. How it works: 3 steps max
5. Social proof: format the real quotes above as testimonials
6. What's included: bullet list
7. Price + CTA
8. FAQ: 3-5 questions (use objections from my outreach if I had any)

Write it ready to paste into a landing page builder. No placeholder text — every word should be final copy. Match the tone of someone who's a peer, not a vendor.
```

## Anti-patterns

- **Don't generate a prompt for everything.** If the skill can answer from methodology, answer directly. The prompt factory is for EXTERNAL knowledge, not laziness.
- **Don't generate vague prompts.** "Research my market" is useless. Every prompt must have their specific product, audience, and constraints baked in.
- **Don't make the buyer do context-gathering.** The whole point is that the Build Partner already has the context. The generated prompt should be copy-paste ready with zero edits needed.
- **Don't send them on a 30-minute research trip for a 2-minute question.** If they ask "should I use Carrd or Framer?" and their product is a $19 ebook, the answer is Carrd. Don't generate a prompt for that — just say Carrd and move on.
- **Don't forget to tell them what to bring back.** Every prompt ends with "come back and paste [specific thing] — I'll save it to your context."
